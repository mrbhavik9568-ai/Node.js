# Security Review & Considerations for OLX Image Upload Feature

## Overview (Task 5)
In an OLX-style public marketplace, allowing users to upload product images introduces critical attack surfaces. A naive implementation generated by basic AI prompts often only looks like this:

```javascript
// Naive AI generated implementation (Vulnerable)
const upload = multer({ dest: 'uploads/' });
app.post('/upload', upload.single('image'), (req, res) => {
  res.json({ url: '/uploads/' + req.file.filename });
});
```

Below is the security analysis and the key improvements implemented in our `olx-clone` app.

---

## 1. Key Security Consideration: Preventing Arbitrary File Execution & MIME Spoofing
### The Threat:
Attackers can upload malicious executable scripts (e.g., PHP, ASPX, Node scripts, or Polyglot web shells) masked with fake file extensions like `shell.php.jpg` or spoofed `Content-Type: image/jpeg` headers. If the web server or static file handler executes or interprets these files, the attacker achieves **Remote Code Execution (RCE)**.

### Improvement / Fix:
1. **Never trust client-supplied extensions or MIME headers alone**: Check both file extension whitelist (`.jpg`, `.png`, `.webp`) and verify actual image header bytes ("Magic Bytes") using libraries like `sharp` or `file-type`.
2. **Re-encode uploaded images**: Passing uploaded images through an image processing pipeline (e.g., resizing or stripping EXIF metadata with `sharp`) destroys malicious embedded PHP/JS payloads.

---

## 2. Denial of Service (DoS) Prevention via Strict File Size Limits
### The Threat:
Unconstrained file uploads allow attackers to upload multiple gigabyte-sized files, filling up server disk space (Inodes exhaustion) and causing system crashes.

### Improvement / Fix:
- Enforce strict size boundaries:
  ```javascript
  const upload = multer({
    storage: storage,
    limits: { fileSize: 2 * 1024 * 1024 } // 2 MB limit per image
  });
  ```

---

## 3. Path Traversal & Filename Sanitization
### The Threat:
User-controlled filenames containing directory traversal characters (e.g. `../../etc/cron.d/malicious`) can overwrite existing system files.

### Improvement / Fix:
- Discard the client's original file name completely. Generate a cryptographic or timestamp-based unique ID:
  ```javascript
  const uniqueName = `olx_img_${Date.now()}_${Math.random().toString(36).substring(2, 9)}${ext}`;
  ```

---

## 4. Production Architecture: Offloading to Isolated Object Storage (AWS S3 / Cloudflare R2)
- In production, never save user-uploaded content on the web application container/server.
- Upload directly to an isolated bucket using pre-signed S3 URLs.
- Serve uploaded images from a CDN domain (e.g. `media.olx-clone.com`) with HTTP headers:
  - `X-Content-Type-Options: nosniff`
  - `Content-Security-Policy: default-src 'none'`
